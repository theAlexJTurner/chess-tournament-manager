# Stakeholder Analysis

## Problem Being Solved

Tournament organizers need a reliable way to create and run Swiss-system chess tournaments without manually maintaining player lists, pairings, colors, byes, results, scores, and standings. The system should reduce administrative work while making the Swiss pairing process consistent, traceable, and usable during a live tournament.

## Stakeholders

| Stakeholder | Interest / Need | Influence |
|---|---|---|
| Tournament Organizer | Create and configure tournaments, register players, generate and review pairings, enter results, manage rounds, handle exceptions, and produce final standings. | High |
| Chess Club / Tournament Organization | Reliable tournament administration, consistent rules, reusable tournament records, and reduced administrative workload. | High |
| Tournament Participants | Accurate pairings, colors, results, standings, and tournament information. | Medium |
| Tournament Director / Arbiter | Ability to enforce tournament rules, resolve pairing conflicts, correct valid administrative errors, and complete tournaments accurately. | High |
| Software Maintainer / Developer | Maintainable requirements, testable pairing behavior, reliable data storage, and a clear separation between tournament logic and the user interface. | Medium |
